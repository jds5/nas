# 2026-10-06 Gopeed 与 JDownloader 部署

用户要求 JDownloader 应对国外网盘，Gopeed 应对百度与夸克，并直接完成百度鉴权。现场核对为 `ynas` Debian，LAN `192.168.50.33`，`/opt/nas/cache` 位于 SSD `/dev/nvme0n1p3` ext4；现有 restic 脚本明确排除此目录，nas-config Git 同样排除。未变更备份脚本、存储布局或已有下载任务。

## 部署结果

| 服务 | 内网入口 | 宿主下载目录 | 配置说明 |
| --- | --- | --- | --- |
| Gopeed v1.9.3 | http://192.168.50.33:9999 | `/opt/nas/cache/gopeed/downloads` | [使用、来源与回滚](../../apps/gopeed/README.md) |
| JDownloader 2 | http://192.168.50.33:5800 | `/opt/nas/cache/jdownloader/downloads` | [使用、来源与回滚](../../apps/jdownloader/README.md) |

两者用户名 `yao`，初始密码沿用已有 OpenList 网页入口，凭据仅保存在 NAS 私有目录。Gopeed 使用原生登录；JDownloader 由独立 nginx Basic Auth 保护整个桌面及 WebSocket。仅绑定 LAN，各自独立 Docker bridge，不连接公网反代，无 Docker socket。关闭浏览器后下载继续。

Gopeed 安装百度扩展 v1.3.7 与夸克扩展 v1.0.4。通过 OpenList 管理 API 在内存中读取已授权配置，将百度 OAuth client_id/client_secret/refresh_token 与夸克 Cookie 写入 Gopeed 私有数据库，无需用户再次授权。百度刷新令牌后成功取得目录和下载地址；夸克关闭自动删除云端转存文件。扩展安装阶段临时使用现有 NAS 代理，完成后恢复 Gopeed 代理关闭。

Gopeed 默认同时运行 2 个文件，每文件 4 个 HTTP 连接，不自动解压。下载及运行配置均位于备份排除区；本仓库只保存无密钥 Compose、Dockerfile、网关配置和维护说明。

JDownloader 首次核心更新直连较慢，已备份 InternetConnectionSettings 并将其 HTTP 代理设置为现有 NAS `192.168.50.33:7890`，由既有规则决定出口。未修改系统全局代理。还原方法见 JDownloader 维护说明。

## 验证

- Gopeed 原生登录 API 和浏览器登录均成功，匿名 API 返回 401。
- 百度 `/PPSA03671` 解析 25 个文件，测试下载 279,475 字节后暂停；重建容器后进度保留，继续至 834,389 字节，再暂停并清理本次测试任务。
- 夸克根目录递归解析 33 个文件；248,789 字节测试文件完整下载，与独立云端读取的 SHA-256 相同，测试任务已清理。
- JDownloader 入口匿名 401、正确凭据 200；首次核心与插件更新完成，浏览器实际进入 Downloads / LinkGrabber 主界面，WebSocket 连接正常。默认路径 `/output` 已核对，Java 运行 UID 1000。尚未进行用户国外网盘账户的下载测试。
- 原 OpenList 与百度 Rust 服务保留，原下载任务没有迁移、停止或清理。新下载器没有留下测试任务。

尚未验证 100 GB 完整传输、长期临时链接刷新、分享转存，以及任何国外网盘付费账户的认证与实际下载速度。百度扩展仅支持自己的云盘目录，分享链接应先转存；夸克分享下载仍受转存空间限制。

## 回滚

本次只新增两套独立服务，停用对应 Compose 即可，命令见应用说明。保留 SSD 中的配置及下载目录，不删除原任务或旧服务。Gopeed 初始下载配置另存于私有目录供维护对照；凭据、Cookie、日志和浏览器验收截图不进入仓库。
