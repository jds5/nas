# 备份盘休眠配置（sda / sdb）

> **迁移说明（2026-09-10）**：来自 Homeland；原文中的“本轮”“已完成”和版本信息保留原记录日期，本次未复验现网。

> 本文档定位：记录两块**备份盘**（非 16T 主存储）的硬盘休眠（spin-down）省电方案 —— 现场确认、能力验证、踩坑、最终方案与持久化。
> 配套文档：[运维记录.md](运维记录.md)（NAS 总体运维）、预算口径见 [`docs/装修总预算主文档.md`](../../../homeland/docs/装修总预算主文档.md)（NAS 为业主个人设备，已从总价剔除）。
>
> **范围**：仅 `sda`（secondary-mirror）+ `sdb`（critical-mirror）。**16T `sdc`（pool-main）不在范围内，全程不动**（APM not supported，关联服务多需常转）。

## 二、唤醒来源与访问节奏（已核实）

通过 root crontab 不可读、改由 restic 日志时间戳 + systemd timers + 容器 inspect 综合判断：

| 时间 | 任务 | sdb（critical-mirror） | sda（secondary-mirror） |
| --- | --- | --- | --- |
| 02:00 | restic-backup（写快照） | **写** | — |
| 06:00 | restic-mirror（rsync） | **读** | **写** |
| 07:00 | restic-onedrive（rclone 读 sdb → OneDrive） | **读** | — |

- 合法访问**集中在 02:00–07:00 晨间窗口**，其余时间空闲 → 理论可睡 ~18 h/天。
- `restic-backup.log` 中 06-15 19:19、06-08 19:15 是**手动临时跑**，非排程。
- `git-backup`（04:00）操作 `/opt/nas/.git`（NVMe），**不碰**这两块盘。

### 后台轮询是否会唤醒？（关键，已实测排除）

- **smartd**：`DEVICESCAN -n standby` —— 盘在 standby 时**跳过** SMART 轮询，不唤醒。✅
- **beszel-agent**：`EXTRA_FILESYSTEMS=sda,sdb,sdc` + 三个 mirror 目录只读挂载，但**无 `/dev/sdX` 块设备透传、无 smartctl** → 只读 `/proc/diskstats`（内核计数）+ `statfs`（缓存超级块），不产生盘片 I/O。
- **实测验证**：手动 `hdparm -y` 强制两盘进 standby 后，连续 6 次采样（45s 间隔、~3m45s，覆盖 ~4 个 beszel 轮询周期）**全程保持 standby**，无人为访问。结论：后台轮询**不会**唤醒休眠盘。✅
- **`/proc/diskstats` 增量**：15s 空闲窗口内 sda/sdb 读写计数**零增长** → 文件系统确实空闲，无周期写入。

## 三、休眠能力实测（重要：两盘行为不同）

| 测试 | sdb（Barracuda） | sda（Toshiba P300） |
| --- | --- | --- |
| `-y` 立即 standby | ✅ 进入 standby | ✅ 进入 standby |
| `-S 1`（5s 空闲计时器）自动 spindown | ✅ 35s 后 = `standby` | ❌ 35s 后仍 `active/idle`（零 I/O 也不睡） |
| `hdparm -I` 能力 | Power-Mgmt feature set `*`enabled；APM=254 | Power-Mgmt feature set `*`enabled；APM=off/disabled |

**结论**：
- **sdb** 支持 ATA 标准 standby 计时器（`hdparm -S`），可自动空闲休眠。
- **sda（Toshiba P300）固件忽略 `-S` 计时器**（接受命令返回成功，但不实际自动 spindown），只认 `-y` 立即 standby。这是 P300 已知固件特性。
- 因此**单一 `hdparm -S` 配置无法同时覆盖两盘** → 改用 `hd-idle`（用户态监控 diskstats，空闲后主动下发 standby 命令，走 sda 也认的"立即 standby"路径）。

## 四、SMART 现状与唤醒代价评估（已读）

两盘 `SMART overall-health: PASSED`，Reallocated / Pending / Uncorrectable **全 0**。均为**已重度使用**的二手备份盘（寿命靠三层备份架构兜底）。

| 属性 | sda（P300） | sdb（Barracuda） |
| --- | --- | --- |
| Power_On_Hours | 25,495 h（~2.9 年） | 27,843 h（~3.2 年） |
| Start_Stop_Count | 20,855（归一化 95） | 24,255（归一化 77 / 阈 20） |
| Load_Cycle_Count | 20,879（归一化 83） | 139,826（归一化 31） |
| Reallocated / Pending | 0 / 0 | 0 / 0 |

**代价测算**：每次 spindown ≈ Start_Stop +1 且 Load_Cycle +1。按晨间排程，sda ~1 次/天、sdb ~3 次/天 →
- sda ~+365/年（对 20,855 基数，可忽略）
- sdb ~+1095/年（对 139,826 基数 **+0.8%/年**，对额定 ~30 万+ 仍可忽略）

**结论：休眠对寿命影响可忽略，省电与降噪收益真实，值得启用。**

## 五、最终方案：hd-idle（双盘统一）

> ⚠️ **后续更正（2026-06-17）**：经首轮 ~26.6h 监控，**hd-idle 实测几乎未生效**（盘 ~95% 时间在转）。根因：磁盘被 ATA/SMART **passthrough（不计入 diskstats）** 偶发唤醒后，hd-idle 仍以为盘已 spindown 而**永不再下达** → 卡死态。已改用**自纠正 cron**（`disk-spindown.sh`，查真实电源态）取代。完整诊断与修复见 [备份盘休眠监控.md 第六、七节](备份盘休眠监控.md)。下文 hd-idle 配置保留作记录。

- 工具：`hd-idle` 1.21（Debian 13 仓库 candidate），用户态守护，监控 `/proc/diskstats`，空闲超时后下发 standby。
- **默认 idle = 0（禁用）** → 不在名单内的盘（含 16T `sdc`）永不被 hd-idle 触碰。
- 仅 `sda` / `sdb` 设 **idle = 1200s（20 分钟）**，按 **by-id** 指定；并用 **`-c ata`**（已实测两盘认 ATA standby）+ **`-s 1`**（运行时解析 by-id 软链）。
- 选 20 分钟：晨间任务结束后约 20 分钟休眠，全天大部分时间睡眠；额外 spindown 次数代价已证可忽略。

**最终生效配置**（`/etc/default/hd-idle`，systemd 服务 `hd-idle.service` 已 enable 开机自启）：

```ini
START_HD_IDLE=true
HD_IDLE_OPTS="-i 0 -c ata -s 1 -a /dev/disk/by-id/ata-TOSHIBA_HDWD130_4948815AS -i 1200 -a /dev/disk/by-id/ata-ST2000DM006-2DM164_Z4ZC2HC9 -i 1200"
```

> `-i 0` 为全局默认 → 未点名的盘（16T `sdc`/pool-main、NVMe、USB）**永不被 hd-idle 休眠**。已实测 `sdc` 不受影响。

### 持久化机制选型说明（为什么不用 /etc/hdparm.conf）

Debian 的 `/usr/lib/udev/hdparm` 辅助脚本会**剥离 `-S`/`-B`**，转交 `/usr/lib/pm-utils/power.d/95hdparm-apm`；而本机 **pm-utils 未安装**（systemd 257，纯 systemd），该委托链不可靠且难验证。故放弃 `/etc/hdparm.conf`，改用 hd-idle 自带 systemd 服务（显式、可测）。
