# NAS 服务与端口清单

最后现场核对：2026-10-07（Asia/Shanghai）。设备：`ynas`，LAN 地址：`192.168.50.33`。

本文持续维护当前端口占用，变更历史通过 Git 追溯；新增、修改、恢复或删除服务后同步更新。网络开放决策以[网络安全架构](../architecture/家庭NAS网络安全架构.md)为准。

## 使用与维护规则

1. 开启端口前先查本表，再核对现场监听、全部容器（包括停止的容器）、Compose/systemd 配置及预留用途。表中没有记录或 `ss` 没有监听，不代表可以直接占用。
2. 分别检查 TCP/UDP、IPv4/IPv6、绑定地址、宿主机端口和容器端口。全地址绑定可能与指定地址绑定冲突；host 网络服务也会占宿主机端口。镜像 `EXPOSE` 不等于发布或实际监听。
3. 管理面按架构默认仅 LAN；需要公网入口时核对反代、路由器映射、防火墙和鉴权。全地址监听不等于已能从公网访问，LAN 绑定也不代替防火墙。
4. 变更完成后核验实际监听及目标网络访问，更新本表的服务、用途、状态、协议、绑定地址、映射、配置来源和核对日期；停用注明是否预留，卸载后注明释放情况。不要记录密码、Cookie 或令牌。

本次依据 `ss -lntu`、`ss -lntp`、`docker ps -a`、选择性 `docker inspect`、进程参数及 systemd 状态核对。未重新验收每项业务功能、反代路径、路由器转发或公网防火墙。

## 现场复查命令

```bash
hostname
ss -lntup
ss -lx
# 包括停止的容器，防止重启时冲突
docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
# 对拟修改的容器分别核对配置和运行态映射；替换容器名
docker inspect --format '{{.Name}} network={{.HostConfig.NetworkMode}} configured={{json .HostConfig.PortBindings}} active={{json .NetworkSettings.Ports}}' 容器名
systemctl list-sockets --all --no-pager
```

此外阅读相应 Compose/systemd/应用监听配置，特别检查 host 网络和停用服务；不要把完整 `docker inspect`、环境变量或含凭据的生产配置粘贴进仓库。普通用户可能看不到其他用户的进程归属；需要权限才能确认时按 `AGENTS.md` 申请权限，不通过修改文件权限规避。
