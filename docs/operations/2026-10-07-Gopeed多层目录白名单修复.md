# 2026-10-07 Gopeed 多层目录白名单修复

## 现象与原因

用户未修改保存目录，夸克文件夹解析成功，在选择包含多层子目录的文件并点击“下载”时收到 `download directory is not in white list`。

现场 Gopeed v1.9.3 默认目录为 `/downloads`，启动配置 `whiteDownloadDirs` 原为 `/downloads` 和 `/downloads/*`。核对本地 v1.9.3 源码：

- `ui/flutter/lib/app/modules/create/views/create_view.dart`：扩展解析后创建批量任务，自动将输入目录、资源名称、文件相对目录拼接为 `opts.path`。因此界面仍显示 `/downloads`，提交给后端的路径可能已是 `/downloads/合集/子目录`。
- `pkg/download/downloader.go` 的 `initOptions` 使用 Go `filepath.Match` 校验白名单；`*` 不匹配路径分隔符，原规则只允许一层子目录。
- `CreateDirectBatch` 逐项创建，遇错即返回，未回滚此前成功项。不能反复点击后假定所有任务均创建失败，重试前应核对任务列表。

这属于部署白名单与网页保留目录结构的行为不匹配，非用户改错保存路径，亦非夸克会员或鉴权问题。

## 变更与备份

将 `/opt/nas/cache/gopeed/private/config.json` 中的 `whiteDownloadDirs` 调整为 `/downloads` 加 1–32 层子目录的模式，共 33 项，生成逻辑为：

```python
['/downloads' + '/*' * depth for depth in range(33)]
```

保留官方二进制、扩展、目录结构及其他下载配置。没有关闭白名单，也没有使用无效的 `**` 递归假设。超过 32 层仍会拒绝，出现此类需求时需另行核对。该白名单是上游字符串 glob 校验，不是路径规范化或 symlink 安全隔离；容器只读根文件系统和既有挂载约束继续保留。

停机前备份配置，停止 Gopeed 后备份任务数据库，随后短暂重启并恢复原来运行的夸克任务。备份位于 SSD 私有目录：

```text
/opt/nas/cache/gopeed/private/whitelist-fix-20261007-012532/
  config.json
  gopeed.db
  before-tasks-summary.json
```

这些属于本次本地回滚快照，沿用缓存目录的自动备份排除，不包含大文件副本，不进入 Git。下载仍落在宿主 `/opt/nas/cache/gopeed/downloads`；入口仍为 `192.168.50.33:9999`，没有增加或改变端口。

首次重启核对任务 ID 时发现 3 条此前删除的百度任务记录重新出现，均为暂停状态，触发了配置回退检查。确认它们是原 `/downloads/PPSA03671` 任务后，用 `force=false` 仅删除旧记录；重新应用白名单，未启动百度下载，未删除用户文件。本次未深入定位旧记录重新出现的底层原因，后续重启仍应核对任务清单。

## 验证

- 修复前，以 `/api/v1/resolve` 请求容器本机未监听的 `127.0.0.1:1`：根目录与一层目录通过白名单后返回连接拒绝，两层目录立即返回白名单错误。此检查未创建任务或下载文件。
- 修复后，同样方法确认根目录、两层及 32 层路径通过白名单；33 层、`/tmp`、`/app/storage` 和 NAS 宿主路径被拒绝。
- 模拟网页调用 `/api/v1/tasks/batch`，两个含中文、多层子目录的测试任务成功创建并排队。测试任务随后仅删除记录，未开始下载，不影响原有任务。
- 原夸克任务 ID 保持不变，重启前约 93,530,487,951 字节，恢复后增长至 94,331,569,551 字节。未做整个大文件完整性校验。
- 宿主机仍仅在 LAN `192.168.50.33:9999/TCP` 提供 Gopeed 入口。
- 请用户在网页重试后，后台实际观察到新增 22 个任务，全部为两层子目录，均成功进入等待队列；原大文件继续运行，进度超过 100,753,795,674 字节。当前并发文件数为 1，等待属于正常排队。用户已明确确认“已正常创建任务”。未验收这 22 个文件的最终下载完整性。

## 回滚

以下只恢复旧白名单配置，会短暂停止下载；回滚后多层目录错误也会恢复。先记录当前正在运行的任务 ID，重启后通过网页或 API 恢复这些任务。不要恢复旧数据库覆盖新增任务与下载进度。

```bash
cd /home/yao/code/nas
docker compose -f apps/gopeed/compose.yaml stop -t 45 gopeed
# 原位覆盖配置以保留单文件 bind mount 的 inode；命令不输出凭据。
python3 - <<'PY'
from pathlib import Path
backup = Path('/opt/nas/cache/gopeed/private/whitelist-fix-20261007-012532/config.json')
target = Path('/opt/nas/cache/gopeed/private/config.json')
with target.open('wb') as stream:
    stream.write(backup.read_bytes())
PY
docker compose -f apps/gopeed/compose.yaml start gopeed
```

恢复后核对任务、进度与绑定端口，按[服务与端口清单](服务与端口清单.md)更新实际状态。
