- 下载后 SHA-256 与 GitHub 发布元数据一致：`452afcb66bfc647ae11dbadadf0ac541e5449e2f81a0ca1ec9dd53065dda8840`。
- 导入镜像 ID：`sha256:8f635868d03316141487bcc1861eb4605d02cc003f540d44adbdc0e6dcc60cce`，架构 amd64，Compose 按 ID 固定并禁止自动拉取。
- 专用 Nginx 入口按仓库摘要固定：`sha256:0985e772fb9f729e6fa0980da05fca5d9c468e870eed43071545afa9d2e27d94`。
- 初次仅绑定 loopback 验证认证，再发布到 LAN IP。Rust 后端不发布宿主端口；两容器同独立 bridge，不加入 NPM 网络。
- 上游 `web_auth/middleware.rs` 放行部分认证和 WebSocket 路径，因此使用入口全路径 Basic 认证，并校验 Origin、拒绝跨站请求。没有依赖上游内置密码模式作为唯一边界。

- 读取现有 Go 客户端的当前账号 Cookie，仅在本机内存中提交给新服务完成登录；未输出 Cookie、改动 CLI 配置或把配置文件挂进 Web 容器。

源码对比及运行配置见 [Web GUI 目录](../../apps/baidupcs-web/README.md)。所有新增运行数据和凭据在 `/opt/nas/cache/baidupcs-downloads/.web-state/`，下载在 `/opt/nas/cache/baidupcs-downloads/web/`。发布镜像包和来源摘要保存在 `.web-state/artifacts/`，便于重建。
