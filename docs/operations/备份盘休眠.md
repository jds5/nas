> 设备名 `sda/sdb` 可能随重启换序，所有持久化配置一律绑 **by-id**。

主存储 `pool-main` 保持常转。调整前核对 by-id、挂载和备份任务，不凭 `sda/sdb` 盘符操作。以下描述原方案，不在本仓库创建或自动运行休眠脚本。

## 最后记录的机制

| 组件 | NAS 上的路径 / 排程 | 作用 |
| --- | --- | --- |
| 自纠正休眠 | `/opt/nas/scripts/disk-spindown.sh`，每 3 分钟 | 查真实电源态与 diskstats 增量，active 且空闲 ≥1200 秒时按 by-id 下达 standby |
| 休眠状态 | `/opt/nas/scripts/.disk-spindown.state` | 每盘 I/O 计数与空闲起始时间 |
| 转换监控 | `/opt/nas/scripts/disk-power-monitor.sh`，每分钟 | 仅状态改变时写日志 |
| 监控日志与状态 | `/opt/nas/scripts/disk-power.log`、`.disk-power.state` | 记录唤醒、休眠和上次状态 |
| 报告 | `/opt/nas/scripts/disk-power-report.sh` | 当前状态、计数及最近转换 |

真实块 I/O 重置空闲计时；passthrough 唤醒若无块 I/O，脚本根据真实 active 状态在下次周期重新休眠。2026-06-17 原记录称短阈值测试和偶发唤醒后的复睡均通过。hd-idle 当时仍为 enable，建议停用但没有后续执行证据；清理前先核对 cron 确实正常接管。

## 为什么移除旧方案

- 2026-06-15 实测两块盘都可接受立即 standby；Toshiba 盘在短测试中未按 `hdparm -S` 自动休眠，不能仅根据命令成功认定计时器有效。
- hd-idle 只看 diskstats；ATA/SMART passthrough 唤醒不产生块 I/O 增量时，它可能仍认为盘已休眠，无法再次发出 standby。
- 2026-06-16 首轮约 26 小时观测显示两盘大部分时间仍在转。06-17 观察到一次双盘同时唤醒但 I/O 计数不变，随后由自纠正方案复睡。
- 唤醒源未最终确认。早期短窗口“后台轮询不会唤醒”的结论不能推广为长期保证；删去“休眠对寿命影响可忽略”和预计省电收益等无充分验证的结论。

## 非侵入检查与台账

原监控使用 `hdparm -C` 查询电源态、`smartctl -n standby -A` 在 standby 时跳过 SMART；普通 `smartctl -A` 可能唤醒盘，会影响观测。设备和转接方式变化后需重新核实行为。

确认脚本与设备存在后，在 NAS 上运行报告：

```bash
/opt/nas/scripts/disk-power-report.sh
```
