# 断电重启服务恢复（2026-10-04）

## 现场与原因

在 NAS 本机 `ynas`、用户 `yao` 核对：Debian 13，内核 `6.12.107+deb13-amd64`，检查时启动约 9 分钟。系统盘与 `/mnt/pool-main`、`/mnt/critical-mirror`、`/mnt/secondary-mirror` 均以读写方式挂载，空间充足。挂载正常不等于完成磁盘健康或数据完整性检查。

- 多数容器已自动恢复；Docker、SSH、SMB、cron 运行且已启用，系统与用户 systemd 无失败单元。
- `npm` 自动启动失败：无法绑定当时尚未就绪的 `192.168.50.33:81`。检查时地址已恢复。
- `nas_web_terminal` 自动启动失败：`/tmp` 为 tmpfs，重启后缺少绑定挂载源 `/tmp/tmux-1000`。现场没有默认 tmux socket 或会话。
- 启动 NPM 后音乐、书库返回 502。NPM 实际仅连接 `nas-net`、`nas-terminal-front`，缺少现有生产 Compose 已声明的 `leaf-net`、`expose-net`；音乐、书库仅在 `leaf-net`，NPM 无法解析其容器名。缺失连接的具体形成原因未确定。

## 已执行

1. 确认局域网地址后执行 `docker start npm`。
2. 以 `yao` 执行 `install -d -m 700 /tmp/tmux-1000`，再执行 `docker start nas_web_terminal`。没有创建或恢复 tmux 任务。
3. 将 NPM 原网络状态与生产 Compose 保存到权限受限的 `/home/yao/.nas-maintenance-backups/power-recovery-20261004/`，执行：

   ```bash
   docker network connect leaf-net npm
   docker network connect expose-net npm
   ```

未升级或重建容器，未修改生产 Compose、端口、认证、防火墙或存储配置。`/opt/nas` 中原有运行数据改动未纳入本仓库提交。

## 回滚与遗留

本次新增网络连接如需撤销，可执行以下命令；会再次影响对应反代服务，不应在正常恢复后执行：

```bash
docker network disconnect expose-net npm
docker network disconnect leaf-net npm
```

如需撤销本次服务启动，可执行 `docker stop nas_web_terminal npm`，会中断网页终端和全部 HTTPS 反代入口。不要删除 tmux 目录或 socket：后续可能已有新会话使用。

尚未修复开机依赖顺序：NPM 需要 LAN 地址就绪，网页终端需要 tmux 目录存在。下次重启仍可能复现；系统级持久化修复未执行，`sudo -n true` 显示需要密码。内核日志读取权限不足，未据此判断无磁盘错误。原 tmux 进程已随断电丢失，任务恢复需另行定位持久化记录。
