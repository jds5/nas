# Immich 与机器学习升级

日期：2026-10-09（Asia/Shanghai）。设备：现场核对为 `ynas`，LAN `192.168.50.33`。生产配置位于独立 `nas-config` 仓库 `/opt/nas/immich/docker-compose.yml`。

## 发行说明与升级范围

核对 GitHub Releases 后，选择最新稳定版 **3.3.1**，跳过预发布版；阅读从 3.2.4 跨到 3.3.1 的正式发行说明和官方部署模板。

| 项目 | 升级前 → 升级后 |
| --- | --- |
| Immich Server | 3.2.4 → 3.3.1，固定官方镜像摘要 |
| Machine Learning | 3.2.4-openvino → 3.3.1-openvino，固定官方镜像摘要 |
| 机器学习模型修订 | 默认 main → `MACHINE_LEARNING_MODEL_REVISION=v2` |
| ONNX Runtime / OpenVINO 后端包 | onnxruntime-openvino 1.24.1 → 1.30.0 |

3.3.0 新增人物共享、生日回忆和图片预览质量改进；3.3.1 修复人物共享、工作流顺序等问题。此次关注的机器学习变更包括优化模型推理、OpenVINO 修复和新 OCR 模型支持。**只更新镜像不会完整启用优化模型**，因此在机器学习服务的 `environment` 中显式设置 v2 修订。

官方说明 v2 是同一模型的优化导出，输出数值等价，不需要重新执行全库 AI 任务。本次保留既有模型选择：多语言搜索 `XLM-Roberta-Large-ViT-H-14__frozen_laion5b_s13b_b90k`、人脸 `buffalo_l`、OCR `PP-OCRv5_mobile`；未切换 OCRv6，也未重跑全库缩略图或 AI 扫描。

保留 `/dev/dri`、render 附加组、QuickSync、模型缓存、代理和照片挂载。新版缓存位于原模型目录下的 `v2/`，旧缓存继续保留；多语言搜索新权重约 4.3 GB，首次下载和编译耗时明显高于后续使用。

本次 Hugging Face Xet 下载在尾段持续降速，改用官方仓库固定 v2 提交的 HTTP Range 下载，在私有目录暂存三组模型共 24 个文件：大文件验证官方 LFS SHA-256，小文件验证 Git blob 摘要。全部通过后仅停止 ML，将文件写入各模型的 `v2/` 缓存，再启动 ML 并逐文件复核 SHA-256。模型选择、权重内容和全局代理配置未改变，旧 main 缓存保留。下载辅助脚本及版本/摘要清单位于下述私有备份目录；应用正常运行，推理验收在缓存就绪后重新执行。

PostgreSQL 14.24、VectorChord 0.4.3、pgvector 0.8.1 和 Valkey 9.1.2 沿用现有配套；不升级宿主机。数据库本地补丁镜像的维护方式仍见[上次升级记录](2026-10-07-剩余应用与数据库升级.md)。

## 实施与验证

先下载两个应用镜像，再停止应用写入，执行数据库逻辑备份、Valkey SAVE，停止数据库/缓存后复制物理数据，生成 SHA-256 清单。随后启动原数据库和缓存，单独重建 Server / Machine Learning。

初次 Compose 启动发现 Valkey 的既有多架构固定摘要没有保留在本地镜像索引，故先直接启动既有容器，再以 `--no-deps` 更新应用。随后重新拉取原固定摘要，确认根文件系统、镜像配置与平台均和原镜像一致；Valkey 的生产数据、版本和 Compose 引用未改变。

- Server、Machine Learning、PostgreSQL、Valkey 均 healthy，RestartCount=0，未 OOM。
- 4 项数据库迁移成功，包括人物共享表及约束变更。
- 升级前停止写入后的基线与升级后数量一致：**563 个资源、2 个用户、2 个图库、0 个相册、13 个人物、658 条人脸记录、553 条搜索索引**。
- 隔离 PostgreSQL 容器从本次物理备份启动，读出全部上述数量并与基线一致。测试容器使用 `--network none`，无生产挂载或发布端口，验证后删除测试容器与测试卷。
- 真实域名/SNI、证书校验通过的 NAS 源站 HTTPS `:8443`：首页 200，版本接口为 3.3.1，ping 为 pong，匿名 `/api/users/me` 为 401。
- Server 到 `immich-machine-learning:3003/ping` 返回 200 / pong；机器学习容器确认为 v2 修订，ONNX Runtime 可用后端包含 OpenVINO 和 CPU，OpenVINO 实际枚举到 CPU / GPU，设备编号为 0。
- 使用生产 ML `/predict` 接口实测四项推理：中文文本与真实图片均返回有效的 1024 维搜索向量，范数分别为 0.99935 / 1.00046；样本识别出 1 张人脸，嵌入向量有效；OCR 正确识别合成测试文字 `IMMICHUPGRADE2026`。测试没有向照片库写入资源或触发全库任务。
- 六类模型会话（文本、图像、人脸检测/识别、OCR 检测/识别）的编译缓存均记录 `openvino/12.4.0-32eu`，确认实际使用 Intel 核显；缓存清单记录 OpenVINO 2026.5.0。文本模型热请求约 0.15 秒；图像、人脸、OCR 首次请求分别约 22.38 / 10.18 / 8.60 秒，包含首次编译，不作为性能对比基准。
- 全部容器的名称集合、挂载、网络成员、设备与端口映射保持不变；宿主机 TCP/UDP、IPv4/IPv6 监听集合与升级前完全一致。

Server 启动存在 `/api/*` 路由自动转换提示，HTTP 验证正常；模型仓库提示未提供 Hugging Face Token，不代表推理失败。不把健康检查或源站请求等同于手机外网验收：本次未测试真实手机上传、后台同步、蜂窝网络或全库 AI 质量。

## 端口与访问边界

四项服务均未发布宿主机端口。Server 实测容器内 `[::]:2283/TCP`，Machine Learning 为 `[::]:3003/TCP`；前者仍经 NPM `:8443` 提供 HTTPS，后者仅供内部推理调用。配置仍使用既有 `nas-net` / `expose-net`，此次没有迁移到目标架构的独立 front/back 网络，也没有新增公网入口、修改防火墙或端口预留。

## 备份与回滚

私有备份目录，不入 Git：

```text
/home/yao/.nas-maintenance-backups/immich-20261009/
```

包含升级前 Compose、`.env`、容器信息、数据库逻辑备份 `immich.dump`、停止服务后的 `postgres.tar` / `redis.tar`、`backup-sha256.json`、验证记录和回滚脚本。旧镜像保留为 `nas-rollback/<容器名>:immich-20261009`。照片原文件和旧模型缓存未复制、迁移或删除；本次数据库恢复测试不代替照片备份恢复演练。

官方不支持仅切旧镜像的版本降级。本次回滚脚本会校验备份摘要，停止四项服务，把当前 PostgreSQL / Valkey 数据目录改名保留为 `.post-upgrade-时间戳`，恢复旧数据库和队列，再恢复旧配置及旧应用本地镜像标签。执行前须核对回滚时间点和升级后的新增数据影响，不会自动合并新数据。

确认需要回滚后执行：

```bash
python3 /home/yao/.nas-maintenance-backups/immich-20261009/rollback.py --confirm
```

依赖 Python 3、Docker/Compose 和生产目录写权限，仅影响 Immich 四项服务。脚本语法已检查，**未在生产执行整套回滚**；数据库物理恢复已完成隔离实测。回滚后重新验证服务版本、数据数量、模型推理和 HTTPS，并同步生产配置仓库与本记录。
