# 2026-10-07 Gopeed 夸克下载调优

> 后续状态：同日已移除 Gopeed 百度插件及 25 条百度任务记录，保留下载文件；并行任务上限降为 1，单文件仍为 256。详见文末。

用户授权调查当前会员等级对应的下载配置，并实际调整 Gopeed 测速。现场为 ynas Debian，Gopeed v1.9.3，SSD 下载目录仍为 `/opt/nas/cache/gopeed/downloads`，继续排除自动备份。

## 会员与接口核对

以 Gopeed 已保存 Cookie 查询夸克官方 `/1/clouddrive/member`，返回 `member_type=EXP_SVIP`；身份信息显示 88VIP 分发来源，付费 `VIP`、`SUPER_VIP` 状态为 `UNPAID`。因此属于 88VIP 联名权益，不能等同直接购买的完整 SVIP，也不能据此断言没有高速下载能力。

[quark-auto-save 源码](https://github.com/Cp0204/quark-auto-save/blob/main/quark_auto_save.py) 同样将 `EXP_SVIP` 映射为 88VIP。[夸克官方传输设置说明](https://www.quark.cn/documents/help/fast-download) 提供限速、并行任务控制，但未给出该等级在第三方下载器中的固定速度承诺。本次未购买、升级会员或修改会员身份。

现用[夸克扩展](https://github.com/iGwkang/gopeed-extension-quark) 调用 `drive-pc.quark.cn/1/clouddrive/file/download?pr=ucpro&fr=pc`，携带登录 Cookie、PC 客户端 User-Agent 与 Referer，未发现独立的会员极速开关。扩展文档推荐 256 连接；原部署为兼顾百度，通用 HTTP 默认值设为 4，本次实测确认它明显限制了夸克吞吐量。

## 同文件对照

使用相同 148,192,775,768 字节文件及同一下载请求，在独立 Gopeed v1.9.3 测试容器内顺序测试。测试实例仅绑定 `127.0.0.1:10099`，启用认证，下载至 SSD 独立临时目录；测试时暂停原夸克任务，百度继续运行。每档约 45 秒，取最后约 30 秒字节增量计算平均速度，未把瞬时峰值作为结果。

| 每文件连接数 | 平均 MiB/s |
| --- | --- |
| 4 | 0.387 |
| 16 | 1.563 |
| 64 | 6.198 |
| 128 | 12.525 |
| 256 | 25.021 |

各档连接统计未发现失败。当前条件下吞吐量近似随连接数增长，支持“单连接限制是主要瓶颈”的判断；不构成所有文件、所有时段或会员等级的速度保证，也未证明 256 是绝对上限。本次选择实测最高且符合扩展建议的 256，不继续增加连接。

## 应用与续传

HTTP 默认连接数改为 256，同时运行任务上限仍为 2，代理保持关闭。Gopeed 配置 API 与宿主启动配置同步更新。该默认值对未来普通 HTTP/百度任务也生效；已有百度任务的显式 4 连接保持不变，新建百度任务建议手动设为 4。

源码核对发现 v1.9.3 的 HTTP `Patch` 不应用 Options，恢复任务时也仅重启已有分片，因此只改默认值不能加速现有 4 分片任务。先在独立测试任务上验证离线转换：停止实例、备份数据库、仅拆分未下载区间，保留预取前缀、每个原分片的已下载前缀与字节计数；检查区间连续、无重叠、总长度一致。试验恢复后实际出现 256 连接，进度增长且速度约 25.9 MiB/s。

随后短暂停止生产 Gopeed 并备份 Bolt 数据库，只更新目标夸克任务的 `task` / `save` 记录，未修改下载文件内容。原已下载 305,027,599 字节全部保留，未删除或重建用户任务。启动后恢复下载，实际连接数 256。其他任务的记录未修改；服务重启期间百度有短暂停顿。

原任务四个分片各抽取 64 KiB，与官方同范围响应做 SHA-256 比较，核对保存的下载内容。未执行整个 148 GB 文件的完整校验；最终完整性须等任务完成后验证。

生产任务恢复后的连续观测速度为 25.47–26.00 MiB/s，256 连接未发现失败，已下载计数增长至 1,587,539,087 字节。重启会将原运行/等待任务置为暂停，已按停机前状态恢复：共 26 个任务，2 个运行、24 个等待，全部百度任务仍为 4 连接。

## 私有证据与回滚

备份、脱敏前 API 响应、测速数据、临时维护程序仅存放于 `/opt/nas/cache/gopeed/private/tuning-20261007/`，不进 Git。`production-migration-v2/gopeed-before.db` 为停止服务后的备份；`task.json`、`save.json` 为转换前目标任务记录。维护程序使用 bbolt v1.4.3，与服务依赖一致。

回滚连接数与目标任务检查点可执行以下命令，下载文件保留，检查点之后的部分数据会重新下载；不要在运行中改数据库：

```bash
docker stop nas-gopeed-gopeed-1
python3 - <<'PY'
import pathlib, subprocess, shutil
p = pathlib.Path('/opt/nas/cache/gopeed/private/tuning-20261007')
db = '/opt/nas/cache/gopeed/storage/gopeed.db'
task_id = (p / 'production-id').read_text().strip()
for bucket in ('task', 'save'):
    subprocess.run([str(p / 'helper/bolt-helper'), 'put', db, bucket,
                    task_id, str(p / 'production-migration-v2' / (bucket + '.json'))], check=True)
subprocess.run([str(p / 'helper/bolt-helper'), 'put', db, 'config', 'config',
                str(p / 'config-pre-apply.json')], check=True)
shutil.copyfile(p / 'startup-config-before.json', '/opt/nas/cache/gopeed/private/config.json')
PY
docker start nas-gopeed-gopeed-1
```

启动后从网页按停机前状态恢复原夸克及其他运行、排队任务。回滚使用原 4 分片记录，不恢复整库，避免覆盖其他任务的新状态。测试任务与测试下载文件已清理，临时测试容器和 loopback 10099 入口已移除。

## 同日后续：移除百度与核查夸克连接限制

用户要求 Gopeed 不再处理百度，以免通用高连接数误用于百度；百度后续使用现有 Rust 服务。通过 API 先暂停全部百度运行/等待任务，再以 `force=false` 删除 25 条任务记录，保留下载文件；随后删除百度扩展，Gopeed 同时清除了该扩展的活动配置、私有存储及安装目录。未撤销 OpenList 的百度 OAuth，未变更 Rust 服务。

官方[下载帮助](https://www.quark.cn/documents/help/fast-download) 只说明限速与并行文件任务设置，未给出 VIP 单文件 HTTP 连接上限。[官网介绍](https://pan.quark.cn/articles/003) 提到 VIP/SVIP 最高下载速度，但该指标不能换算成允许连接数，也不是 88VIP 联名权益的保证。公开第三方方案中的 16/32/256 属其自身配置，不足以认定为官方阈值。因此未声称已套用官方 VIP 上限，未继续增加连接。

将 `maxRunning` 从 2 降为 1，并同步启动配置，避免多文件叠加为 512 个连接。单文件仍保留此前实测的 256；这是本地控制选择，不是“免封禁”保证。验收：只剩夸克扩展和 1 条运行中的夸克任务，Rust 认证入口返回 401（登录保护正常）。

本次变更前配置、百度任务元数据及扩展配置保存在 NAS 私有目录 `/opt/nas/cache/gopeed/private/remove-baidu-20261007/`，未提交凭据。若需回滚并行上限，可在 Gopeed 设置中改回 2，并同步私有启动配置；百度扩展不自动恢复，应遵循用户后续明确要求。此前整库/配置备份包含旧百度信息，维护时不得盲目覆盖现状。
