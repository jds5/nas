# 手机接续 Codex 会话：设计与验收

更新：2026-09-28。Android 专用 App 已实现基本内外网连接，用户真机反馈连接成功；0.5.0 增加已退出会话恢复与新项目启动，支持已有目录、空目录、Git 克隆及显式快速前进拉取。本文件末尾保留设计与验收范围，实际实现差异见本节末尾。公网入口以 [网络架构](../architecture/家庭NAS网络安全架构.md) 和 [SSH 配置手册](手机外网连接与SSH密钥配置.md) 为准，不要求必须使用 VPN。2026-09-10 的初始调研及阶段方案通过 Git 历史追溯。

## 当前路径

```text
Android App → 已固定指纹的公钥 SSH → NAS 原 tmux / Codex
  ├─ 默认聊天：进程打开的 rollout → 公开消息 → 原生聊天列表
  ├─ 一次发送：核对会话与空草稿 → bracketed paste → 核对 → Enter
  ├─ / 命令与技能；! 交给 Codex shell 模式
  ├─ 图片/文件：SSH 私有目录 → 校验 → 原会话读取路径
  └─ 可选终端：屏幕快照、粘贴、回车及特殊键
```

保留当前执行器，不启动第二个 Codex，不 `resume`、`fork` 或更改终端尺寸。桥接是随 APK 打包的 Python 脚本，每次通过 SSH exec 临时运行，无监听端口、常驻进程、账户系统或额外 NAS 安装。依赖 Linux `/proc`、Python 3.9+、默认 tmux socket；本机验证 tmux 3.5a、Codex CLI 0.154.0。

通过 pane 的进程树、Codex 打开的文件描述符、进程启动时间、文件 inode 和会话 ID 建立关联；不根据工作目录或文件新旧关联。只读取 typed public message events，不展示 reasoning、系统/开发者提示或代理工具原始记录。`!` 的明确用户命令结果单独显示。CLI 记录格式不是官方稳定远控协议，升级后需要重新验收；无法确认关联时回到终端模式。

## 手机交互

- 点击 Codex 会话默认打开聊天页；列表和会话顶部提供“终端”入口，保留原模式，其他程序仍只读。
- 普通中文、多行输入点一次“发送”。已有电脑草稿、菜单或确认提示会阻止自动发送，不覆盖原输入。
- 输入 `/` 出现常用命令建议；`/skills` 打开技能列表，选择后插入 `$技能名`，也可调用 Codex 原菜单。
- `!命令` 在 NAS 的 Codex shell 模式执行，使用该会话当前权限。App 不另开绕过 Codex 的 shell 执行通道。
- 异步问题使用原生表单：直接点选或输入自定义回答，一次提交；多题用上一题/下一题，稍后回答返回聊天。无法完整识别时保留手动入口。
- 菜单和审批使用控制面板的实际终端画面与方向键、Tab、确认、Esc，以及 Shift+← 打开/切换问题、Alt+↓ 返回、Other 自由回答；跳过和中断需再次确认。不根据终端文案伪造审批协议。
- 前台只读轮询中断时有限重连接回原执行器，补读消息。返回后台断开 SSH，远端继续运行；主动打开系统文件选择器时允许暂停 SSH 并短时保留解锁身份（最长 120 秒）。发送结果不确定时禁止自动重放，重连查看原窗格并确认后恢复操作。

## 会话恢复与新项目启动设计（2026-09-27，28 日补充 Git 来源；0.5.0 已实现核心流程）

### 目标与现场约束

当前 0.4.2 仅发现已有 tmux 窗格；前台不是 `codex` 时 `Pane.canWrite=false`，手机只能查看。`SshTmuxClient.panes()` 直接调用 `tmux list-panes`，没有 tmux server 时连接阶段会失败。“接回上次会话”要求 pane/server/PID 与旧执行器一致，Codex 退出或 tmux session 消失时按设计拒绝。此前在 NAS 上通过 [精确 ID 恢复脚本](../../scripts/codex/README.md)成功手动恢复 `home`，证明 CLI 恢复路径可行，但手机无法在所有 Codex 都退出时使用 `!`。

把以下三个概念明确分开：SSH 重连仅恢复连接；**恢复对话**继续一个已保存的 Codex UUID；**新建对话**在指定项目目录启动全新的 Codex。用户从会话列表发起后两者，不能由“接回上次会话”自动触发。CLI 的 `codex resume SESSION_ID` 与直接 `codex` 均为[官方开发者命令](https://learn.chatgpt.com/docs/developer-commands)；不用 `resume --last`、不按目录最新记录猜 UUID，也不把 `codex exec resume` 当作交互式 tmux 会话。

### 手机界面

| 入口 | 显示与操作 | 完成后的去向 |
| --- | --- | --- |
| 会话列表中的空闲 shell 窗格 | 显示“Codex 已退出”，提供“恢复此会话”；先展示该窗格原目录中已保存的候选对话（本机别名如有、目录、创建时间、UUID 后段），用户选精确 UUID | 在同一窗格启动并重新绑定；目录、窗格身份或输入行不符时停止 |
| 旧窗格已消失 | “恢复历史对话”；先选保存的 UUID，再确认目录及新的 tmux 名称 | 新建一个 tmux session，在其中继续该 UUID |
| 项目入口：已有目录 | 选项目路径和唯一 tmux 名称；默认不更新 Git，可单独选择“先更新已有仓库” | 在当前目录新建 tmux session 并运行全新 `codex` |
| 项目入口：空目录 | 在允许的项目根目录下创建一个空子目录，填写唯一 tmux 名称 | 在新目录启动全新 `codex` |
| 项目入口：Git 仓库 | 输入仓库地址、目标目录名和唯一 tmux 名称；先预览来源与落盘路径，再执行克隆 | 仅在克隆、检出和目录校验完成后启动全新 `codex` |
| 空列表 / 无 tmux server | 仍显示上述“恢复历史对话”和“新建项目会话”；普通会话列表为空不阻止建立 SSH 连接 | 同上，创建时由 tmux 启动默认 server |

候选列表只读会话 `session_meta`，限制扫描文件数、文件大小和结果条数；不把历史正文、凭据或完整 rollout 发到手机。列表区分“该 UUID 已在其他窗格运行”，这种候选只能跳转现有窗格，不能重复 resume。过时的候选目录、重复 UUID、不可读记录应标明原因并禁用启动。选项中展示实际绝对路径与将执行的动作，单次明确点击“启动”；不自动选择最新一项，也不以手机保存的旧 pane ID 代替 UUID。

### NAS 端协议与执行顺序

在 APK 自带的无状态 Python 桥接器增加 `list_saved_threads`、`prepare_lifecycle`、`start_lifecycle`、`inspect_lifecycle` 四类 JSON action；请求数据只走 SSH stdin，tmux 用参数数组调用。对现有 shell 发送的固定命令仅由已解析的 Codex 绝对路径、`resume` 子命令和已验证 UUID 组成，按 shell 规则转义；目录通过 tmux 的 `-c` 参数传递，不把用户自由文本拼进 shell 命令。复用现有主机指纹、公钥认证、SSH 用户和默认 tmux socket，不增加 NAS 常驻服务或公网端口。现有 `snapshot/send/key` 与生命周期操作分离，任何创建动作都不能绕过当前聊天的精确绑定。会话列表对“tmux server 不存在”返回空列表，其他 tmux 错误仍按错误显示。

1. `prepare` 返回预检快照及短期有效的摘要：精确 UUID、保存记录 inode/所有者/原目录，或新项目规范化目录；目标 tmux session 是否存在、窗格 ID/PID/server PID/当前命令/目录；预计执行 `codex resume UUID` 或 `codex`。`start` 重新计算快照并比对摘要，不依赖跨 SSH 请求的内存状态。恢复到现有窗格仅接受唯一的空闲 shell、无子进程且输入行为空；其他程序、多个窗格、已有草稿或同一 UUID 已在别处运行均拒绝。若窗格已运行同一 UUID，返回“直接打开”。
2. 项目目录默认限定为实际路径位于 SSH 用户的 `~/code` 下，确认目录归属与权限、排除符号链接跨出允许根目录；不接受客户端提供的任意命令。创建新目录只允许一层空目录，名称及父目录再次校验；空目录路径不自动 `git init`。Git 来源的校验与执行见下节。tmux 名称限制为短的字母数字、`_`、`-`，发生重名则要求用户重新命名，不覆盖原 session。
3. `start` 在 NAS 端用同一用户的文件锁串行化预检与启动；复核预检快照中的目标身份和文件状态后才操作。新建 tmux 先创建单窗格 shell、读取其新身份，再发送一次固定的 Codex 启动命令；现有 shell 同样先复核空输入行。对于 tmux 命令已发送但回执丢失的情况，以操作随机 ID 标记新建 session，并由 `inspect` 只读查询；结果不明确时停止，不自动重复创建或按键。手工终端同时写入不能做到绝对原子化，因此每次发送前仍要重新核对画面与进程。
4. Codex 的更新、信任、登录、权限或未知菜单由 App 显示实际终端画面并交给用户处理，不自动确认。启动成功后等桥接器从目标 Codex 进程打开的 rollout 读取精确会话 ID；恢复要求与所选 UUID 相同，新建则记录新 UUID，再建立新的进程/inode/binding。若 CLI 尚未创建 rollout，显示“等待首次对话”并提供受保护的首条输入：确认 pane 身份、Codex 进程启动时间和空输入框后只发送一次，产生 rollout 后才进入普通聊天；如果这一步不能安全验证，回退到只读终端画面，不猜 ID。

### 新项目的 Git 来源

“从 Git 仓库新建”指 **clone 到一个尚不存在的目录**，不是在任意目录执行 `git pull`。预览显示规范化的仓库地址、目标绝对路径和分支选择（默认远端默认分支）；目标路径已存在、tmux 名称重名或仓库地址不合规则停止。仅接受用户输入的 HTTPS URL（不含用户名、密码或令牌）和 SSH URL / `git@主机:仓库`，禁止本地路径、`file://`、`ext::`、以 `-` 开头的参数及任意 Git 选项。桥接器以参数数组运行 `git clone -- <仓库> <临时目录>`，用 `GIT_TERMINAL_PROMPT=0` 和 SSH BatchMode 禁用交互式凭据提示；私库只使用 NAS 上**事先配置且已验证**的 Git SSH 凭据和主机密钥，不复用手机连接 NAS 的私钥，也不在手机保存仓库令牌。认证或主机校验失败时报告原因，让用户在可信 NAS 终端处理，不自动接受未知 Git 主机或回退到 HTTP。

克隆任务可能超过现有 10 秒 SSH exec 时限，因此采用带随机操作 ID 的临时后台任务、0600 状态文件和有界进度查询；无常驻服务。先在 `~/code` 下创建独占的临时目录，克隆、检出并核对 `.git`、工作树根目录、选定分支和 HEAD 后，再以“目标不存在才成功”的原子重命名放入最终路径。只有项目准备成功才创建 tmux 并启动 Codex。SSH 断线后按操作 ID 查询任务和目标目录，不能重复克隆；失败时保留自己创建的临时目录供核对，不覆盖或删除已有目录。仓库 URL、Git stderr 和进度需脱敏且限长，不进入 App 持久草稿或 Git 运维记录。克隆不递归拉取子模块，并设置 `GIT_LFS_SKIP_SMUDGE=1` 防止检出时自动下载 LFS 内容；界面提示仓库可能仍有额外初始化步骤。

“已有目录先拉取”是独立且默认关闭的选项。先核对目录是 Git 工作树根目录、当前有命名分支与上游、工作树和索引干净；用户开启此项后先 fetch，再展示当前 HEAD、远端、分支及将要更新的提交范围，确认后仅允许快速前进更新。出现未提交改动、未跟踪文件可能冲突、分支分歧、认证失败或拉取过程不确定时停止，不自动 stash、rebase、reset、强制覆盖或继续启动 Codex；恢复连接后先核对实际 HEAD 和状态。若用户只想在现有目录启动，可跳过拉取，直接打开该目录。此流程应保存更新前 HEAD 作为核对与人工恢复依据，但不自动执行破坏性的回退。

生命周期操作采用 `预检 → 用户确认 → 准备项目 → 启动中 → 等待绑定 / 待人工处理 → 已绑定` 状态；SSH 断开或超时进入“结果待核对”，重新连接后先 `inspect`，不能自动重放。操作有短期限和客户端生成的随机 ID；失败后新建的空 tmux session 保留供人工检查，本期不提供删除按钮，也不触碰已有 session。现有连接层每次 SSH exec 超时 10 秒，启动可能超过该时限，因此 `start` 应快速返回，后续有限次数轮询 `inspect`，不能让单次 SSH 调用一直等待启动完成。

新执行器的 pane/server/PID 和 Codex binding 必然变化。旧聊天书签只有在**同一 UUID、同一 rollout 文件**核实后，才可选择继承阅读位置；旧的未确认发送状态、问题草稿和待发送附件不得自动移交。新建对话始终使用全新草稿/书签。会话列表将“旧绑定失效”和“可以恢复同一对话”分别展示，防止把上次的输入送到新项目。

### 分期验收

1. 先完成只读历史候选列表与预检，包括无 tmux server、无记录、目录已删除、UUID 重复或已运行、目录越界、窗格多个/忙碌等拒绝路径；不读取正文。
2. 再实现“空闲窗格恢复精确 UUID”及“旧 tmux 消失后新建窗格恢复”，用隔离 tmux socket 和临时 Codex 会话验证：只启动一次、绑定原 UUID、旧草稿不误发、超时后只读核对；已有 `resume_tmux.py` 可作行为参考，不作为 APK 必须依赖的 NAS 安装文件。
3. 最后实现“现有目录/空目录/Git 克隆新建”与显式快速前进拉取，覆盖全无 tmux session、名称冲突、克隆失败或中断、已有目录有改动、无上游分支、启动菜单、首次 rollout 尚不存在、SSH 中断、并发点击及用户在电脑端抢先操作。真机在 LAN 与外网各验收一次：从空列表启动、恢复历史、首条消息、断线后重新选择以及回到旧会话；未做这些测试前不标记功能已交付。

0.5.0 已实现预检、确认、精确 UUID 恢复、新建 tmux、空目录、克隆、显式快速前进拉取和操作 ID 查询。实现采用独立的 `nas_remote_lifecycle.py`，与聊天桥接器分离；新启动后先进入终端模式，由用户处理首次输入，尚未实现“受保护的首条输入自动转聊天”与旧阅读位置继承。历史候选只展示最近 80 条，手动 UUID 可检索更早记录；列表没有标注候选已在运行，预检时会拒绝重复恢复。克隆后核对 HEAD，但不额外确认 `.git` 目录或所选分支；Git 预检显示 HEAD 摘要，不计算完整提交范围。后台克隆或拉取中可以离开界面，返回后从加密保存的操作 ID 查询；手机进程重启、LAN 和外网实机流程仍待验收。原设计中“短期限”和“SSH exec 必须快速返回”未完整落实：克隆/拉取启动快速返回，普通新建等待 shell 提示符最多约六秒。以上差异不应当作已验收能力。
