# 手机接续 Codex 会话：设计与验收

更新：2026-09-17。Android 专用 App 已实现基本内外网连接，用户真机反馈连接成功；0.2.0 调整为默认聊天体验。公网入口以 [网络架构](../architecture/家庭NAS网络安全架构.md) 和 [SSH 配置手册](手机外网连接与SSH密钥配置.md) 为准，不要求必须使用 VPN。2026-09-10 的初始调研及阶段方案通过 Git 历史追溯。

## 当前路径

```text
Android App → 已固定指纹的公钥 SSH → NAS 原 tmux / Codex
  ├─ 默认聊天：进程打开的 rollout → 公开消息 → 原生聊天列表
  ├─ 一次发送：核对会话与空草稿 → bracketed paste → 核对 → Enter
  ├─ / 命令与技能；! 交给 Codex shell 模式
  └─ 可选终端：屏幕快照、粘贴、回车及特殊键
```

保留当前执行器，不启动第二个 Codex，不 `resume`、`fork` 或更改终端尺寸。桥接是随 APK 打包的 Python 脚本，每次通过 SSH exec 临时运行，无监听端口、常驻进程、账户系统或额外 NAS 安装。依赖 Linux `/proc`、Python 3.9+、默认 tmux socket；本机验证 tmux 3.5a、Codex CLI 0.154.0。

通过 pane 的进程树、Codex 打开的文件描述符、进程启动时间、文件 inode 和会话 ID 建立关联；不根据工作目录或文件新旧关联。只读取 typed public message events，不展示 reasoning、系统/开发者提示或代理工具原始记录。`!` 的明确用户命令结果单独显示。CLI 记录格式不是官方稳定远控协议，升级后需要重新验收；无法确认关联时回到终端模式。

## 手机交互

- 点击 Codex 会话默认打开聊天页；列表和会话顶部提供“终端”入口，保留原模式，其他程序仍只读。
- 普通中文、多行输入点一次“发送”。已有电脑草稿、菜单或确认提示会阻止自动发送，不覆盖原输入。
- 输入 `/` 出现常用命令建议；`/skills` 打开技能列表，选择后插入 `$技能名`，也可调用 Codex 原菜单。
- `!命令` 在 NAS 的 Codex shell 模式执行，使用该会话当前权限。App 不另开绕过 Codex 的 shell 执行通道。
- 菜单和审批使用控制面板的实际终端画面与方向键、Tab、确认、Esc；中断需再次确认。不根据终端文案伪造审批协议。
- 返回后台断开 SSH，远端继续运行。发送结果不确定时禁止自动重放，重连查看原窗格并确认后恢复操作。

## 验证与后续

本轮已完成：公开消息过滤/分页、原会话精确关联、隔离 tmux 一次发送、同目录其他会话不受影响、中文多行与长文本识别、真实隔离 Codex 的 `!printf` 和 `/status`、SSH 身份与主机指纹拒绝测试，以及 APK 构建/Lint。当前对话只做读取验证，没有注入测试输入。

仍需手机验收：

1. 覆盖安装 0.2.0，在既有 Codex 会话检查历史、回复和一次发送；复杂表格/图片等不是完整 Markdown 渲染。
2. 验证技能选择、`/model`、权限确认及 `!` 输出；权限变更以原 Codex 菜单为准。
3. 电脑输入草稿时手机应拒绝；发送中断网后先核对，不重发；不要同时在电脑和手机输入。
4. 锁屏、旋转、字体缩放、Wi-Fi/蜂窝切换、DDNS 更新后的重连。
5. Release 真机测量动画帧率与耗电；当前没有设备测量证据。

剩余限制：完成事件写入后才出现消息，尚无逐 token 流式显示；新会话首次产生日志前、超长历史与不兼容 CLI 使用终端回退。未来若转向官方 App Server / Remote Control，应先验证能接入同一运行执行器，再增加流式事件、结构化审批和通知；不以“能读取历史”冒充实时协议接管。

代码结构、上限、构建与使用细节统一见 [App README](../../apps/android/README.md)，风险见 [安全诊断](../security/ANDROID_APP_SECURITY_REVIEW.md)。局域网安装包入口为 **http://192.168.50.33:8765/**，不经 NPM 对公网发布。

## 下一阶段提案（2026-09-17，尚未实现）

产品继续聚焦“从手机接回 NAS 上的 Codex”。优先完善每日使用的可靠性，再增加新入口；以下为讨论建议，不代表已授权实施全部功能。

| 顺序 | 功能 | 用户收益与验收边界 |
| --- | --- | --- |
| P0 | 消息发送状态与草稿恢复 | 显示发送中、已送入终端、结果待确认；有可靠消息证据才标记 Codex 已接收。可选加密保存未发送草稿，以真实会话身份区分；重复点击、断网与进程重启不造成自动重复发送 |
| P0 | 一键接回上次会话 | 重新认证后恢复原会话和阅读位置，按游标补齐离线期间公开消息。前台短断线重连要重新核对主机与会话，原任务变化则停止，不重放输入；保留后台断开默认行为 |
| P0 | 阅读、输入与动画打磨 | 完善列表/表格/代码块，增加消息与代码复制、长输出折叠、未读分隔和回到最新。读旧消息不被拉走，输入法弹出不跳动；在真机 Release 上检查长会话滚动、字体缩放与帧耗时 |
| P1 | 连接自检页 | 显示解析、TCP、SSH、认证、tmux/Codex 各阶段及实际目标地址，生成可预览脱敏的诊断摘要；不得把内网回环成功当成外网可达，不自动改 NAS 防火墙 |
| P1 | 会话列表与命令交互 | 最近会话、收藏/本地别名、未读提示、技能搜索与常用命令；任务状态必须来自可靠事件，危险命令不设计成一键误触操作 |
| P1 | 改动审阅 | 在明确绑定的项目内只读查看 Git 文件变化与 diff，手机上能判断 Codex 改了什么；限制文件大小和路径，默认不读取未跟踪敏感文件，不自动提交或回滚 |
| 后续专项 | 完成通知、真正流式回复与原生审批 | 先验证同一执行器可提供可靠事件、断线恢复及后台投递路径。当前完成事件轮询不能变成真实逐 token 流式，不用猜终端文字来自动批准权限 |

建议下一版先交付前三项，仍不增加 NAS 常驻服务和新公网端口。轮询优化以按文件位置增量读取、活跃/空闲节奏区分和响应大小控制为方向，并以真机流量、耗电、消息完整性与输入响应测量决定参数。加密草稿是可选新能力，默认不引入完整聊天记录落盘。

不同时推进多用户账户、插件市场、完整文件管理器、NAS 监控面板和远程桌面；这些会扩大权限与维护范围，对当前手机接续对话的改善较小。
