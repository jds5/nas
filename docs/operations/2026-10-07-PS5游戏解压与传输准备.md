## NAS 直接上传方法（尚未执行）

在 NAS 终端运行以下命令，可断点续传到扫描范围之外的临时目录。保持 PS5 开机并运行 FTP，关闭自动休眠。传输时使用二进制模式，目录和大小写保持不变。

```bash
LD_LIBRARY_PATH=/opt/nas/cache/gopeed/private/extract-tools/unpacked/usr/lib/x86_64-linux-gnu \
/opt/nas/cache/gopeed/private/extract-tools/unpacked/usr/bin/lftp \
  ftp://192.168.50.38:2121
```

进入 lftp 后：

```text
set cmd:fail-exit yes
set ftp:ssl-allow no
set ftp:passive-mode yes
set net:timeout 20
set net:max-retries 5
mirror --reverse --continue --parallel=1 --verbose "/opt/nas/cache/gopeed/extracted/Wolverine LZ4 PPSA03671" /data/transfer-staging/PPSA03671
```

确认无传输错误、全部 89 个文件完成后，再执行：

```text
mkdir -p /data/etaHEN/games
mv /data/transfer-staging/PPSA03671 /data/etaHEN/games/PPSA03671
bye
```

最终应存在 `/data/etaHEN/games/PPSA03671/sce_sys/param.json`，不额外嵌套原压缩包顶层目录。以上命令在前台运行；若需关闭会话仍持续传输，应在 NAS 的 tmux 会话中执行并分离会话，或交由助手托管后台任务。

ShadowMountPlus 会扫描并注册完整目录；注册后游戏仍依赖这些源文件，不能将其当作安装缓存删除。运行需要与 13.00 适配的 Kstuff 和 ShadowMountPlus；失败时查看 `/data/shadowmount/debug.log`。路径和注册规则来源：[ShadowMountPlus 官方说明](https://github.com/drakmor/ShadowMountPlus#scan-paths)。

## 启动错误 CE-107750-0 排查

后续重启运行环境后，日志确认 `Installed NEW!`，注册成功；启动时目录和 fakelib 均挂载，随后失败。用户确认手动运行 Kstuff；上传的 `kstuff (1).elf` 内嵌版本为 Kstuff Lite 1.11，不能把 ShadowMountPlus 启动时的 `kstuff not present` 当作后续一直未加载。

从 PS5 读取原始数据（本次 FTP 连接关闭 SELF 转换）计算 SHA-256，`eboot.bin`、`sce_sys/param.json`、全部 5 个 fakelib 库与 NAS 副本一致。用户启动 klogsrv 后，助手连接 `192.168.50.38:3232` 捕获系统日志；原始日志仅保存在 `/home/yao/.nas-maintenance-backups/ps5-launch-20261007/kernel.log`，不进入 Git。

系统日志明确报 `processSpawn() error: 0x80aa001a`，`errno=13`。FTP LIST 核实游戏 `eboot.bin` 为 `644`，缺少执行位。通过 ftpsrv `CHMOD 755 /data/etaHEN/games/PPSA03671/eboot.bin` 修正并读取确认，仅修改启动文件模式，不改内容、其他文件或系统权限。回滚为相同 CHMOD 命令使用 `644`。修正后的启动结果待用户复测。

后续 lftp 上传可执行目录时应检查远端执行位，不能仅以数量、大小和哈希作为可运行性验收；本次原 NAS 解压文件也无执行位。


复测确认仅修正 eboot 后，内核出现 `EXEC /app0/eboot.bin`，原进程创建错误已解除；随后 rtld 报 `self_load_shared_object: mount flag / attribute error`，目标是 `common/lib/libSceAmpr.sprx`。继续将游戏内 9 个 `.sprx` / `.prx` 设置为 755；FTP 返回成功，并读取确认 fakelib 及 sce_module 中库的执行位。再次启动结果待确认。NAS 解压目录内同一组 10 个可执行文件（eboot 加 9 个库）也设置为 755，避免后续重新同步又丢失执行位；原 RAR 未修改。
