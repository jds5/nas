## 一、公网四服务安全开放（主线，✅ 已完成）

### 网络突破

- 联通切公网 IP（说辞："远程访问家里设备"）
- 光猫中兴 F657GV 超管改桥接（`2_INTERNET_R_VID_111`，VLAN111，PPPoE）
- AX86U 改 PPPoE 拨号，WAN 获真公网 `122.96.x.x`
- **IPv6**：AX86U 联机类型改 `Native`（非 Passthrough，桥接后 Passthrough 失效），NAS 获公网 v6，IPv6 防火墙已开

### 端口策略（关键发现）

- 运营商**封 443 入站**，`8443` 可用（在 CF 免费版回源白名单 `443/2053/2083/2087/2096/8443` 内）
- 之前 python 测 443 不通是 **UFW INPUT 链 DROP 的假阴性**（Docker 容器走 FORWARD 链绕过 UFW）
- AX86U 最终只一条转发：`8443 → 192.168.50.33:8443`；UPnP / DMZ / OpenNAT 全关

### 网络三层拆分

| 网络 | 服务 | 说明 |
| --- | --- | --- |
| **leaf-net** | Navidrome、Kavita、NPM | 数据面，纯叶子隔离 |
| **expose-net** | NPM、Seerr、Immich-server | 暴露面 |
| **nas-net**（= backend） | arr 全家桶 / qbit / mihomo / 监控 / immich-db-redis-ML / byparr / jellyfin | 后端 |

**跨网枢纽**：NPM（三网）、Seerr（nas + expose）、Immich-server（nas + expose）

> **核心认知**：网络拆分只能隔离"纯叶子服务"；NPM / Seerr / Immich 是枢纽，攻破后穿透挡不住，靠自身更新 + 认证。移除 Komf 使 Kavita 成纯叶子。

### 反代部署（NPM）

- 路径 `/opt/nas/npm`，镜像 `jc21/nginx-proxy-manager`
- 端口：`8443:443` + `192.168.50.33:81:81`（管理面绑内网 IP）
- **Let's Encrypt 通配符证书** `*.rokano.org`（DNS-01，Cloudflare，`dns_cloudflare_api_token=<Token>`，Propagation 60）

四个 Proxy Host（均绑通配符证书 + 强制 HTTPS + HSTS + Block Common Exploits + Websockets）：

### DDNS

- `/opt/nas/ddns-go`，`network_mode: host`，CF + Token

## 二、安全加固（✅ 已完成）

### 端口收紧（解决 Docker 绕 UFW）

- 四服务去掉宿主机端口映射（Navidrome `:4533` / Kavita `:5000` / Seerr `:5055` / Immich `:2283`），只走 Docker 网络由 NPM 容器名反代
- immich-postgres / redis 只在 nas-net，不暴露

### CF 边缘加固（放弃"只允许中国 IP"，保留出国访问）

- **速率限制规则**：URI 路径 `*` / 100 请求每 10 秒 / 阻止
- **自定义规则**：密码泄露 = 开 → 阻止（挡撞库，本会话末尾验证有效 —— 建 Immich 用户填弱密码被 403 拦）
- Bot Fight Mode + Always Use HTTPS
- DDoS 防护（免费版自动始终启用）；WAF Managed Ruleset 是 Pro 功能（免费版无）

### 应用层

- 四服务确认无开放注册（Immich / Seerr / Navidrome 设计上无公开注册，只管理员建用户；Kavita 邀请制）
- Seerr 关本地登录 + 关 Plex 登录，只留 Jellyfin 认证；更新到最新版
- **NPM Basic Auth 决策**：四服务都不加（Immich / Kavita-OPDS / Navidrome-客户端 冲突；Seerr 用户选择不加）
- Kavita OPDS 给 Mihon 用，带 API key 认证非匿名，风险可控

### 服务归属定型

| 归属 | 服务 |
| --- | --- |
| **公网橙云** | Immich / Seerr / Navidrome / Kavita |
| **Tailscale** | Jellyfin（有公网 IP 后 direct 28ms） |
| **纯内网** | arr / qbit / mihomo / 监控 / 数据库 / SMB |

## 三、关键排错经验（踩坑，⚠️ 重要）

### Tailscale DNS 残留致命坑

`tailscale set --accept-dns=false` 只改宿主机 DNS，**不影响已运行容器**（容器 DNS 在创建时继承，之后不变）。关闭 Tailscale DNS 接管后**必须重建所有容器**，否则旧容器一直用缓存的 `100.100.100.100` 解析外部域名失败。

- 本会话 Sonarr 加剧集失败根因就是这个（`skyhook.sonarr.tv` 解析失败）
- 重建所有中招容器（immich 后端 / diun / kuma / mihomo / bazarr / qbit / radarr / prowlarr / jellyfin / byparr）解决
- **排查命令**：遍历容器查 `resolv.conf` 的 ExtServers 是否含 `100.100.100.100`

### gai.conf 设 IPv4 优先

```bash
echo "precedence ::ffff:0:0/96 100" >> /etc/gai.conf
```

解决 docker 优先尝试坏 v6 超时。

### arr 元数据源

- Sonarr 不直连 TheTVDB，走 `skyhook.sonarr.tv`
- Radarr 走 `api.radarr.video`
- Seerr 直连 `api.themoviedb.org` + `api.thetvdb.com`
- gfwlist 模式下这些境外域名需加代理名单

### 报错必看产生错误服务的原始日志

Seerr 转述的 "503" 误导，Sonarr 自身日志才显示真相 `SocketException(11) skyhook.sonarr.tv`（DNS 解析失败）。

### grep -c 退出码断链

`grep -c` 无匹配返回退出码 1，放 `&&` 链会中断后续命令。用 `;` 或 `|| true` 兜底。

## 四、备份架构改造（本会话重点，✅ 已完成）

**问题**：git 备份被应用自动 backup 撑爆，`.git` 达 8.2 G 超 GitHub 2 GB 上限，push 失败数日。

**根因**：`.gitignore` 白名单误放行 backup 的 `.db` / `.zip`；Navidrome 每天 24 M db 累积进 git 历史；实际历史内容仅 455 M，8.2 G 全是冗余松散对象堆积。

### 解决方案（git 管配置 / restic 管数据）

**1. restic 扩展覆盖 `/opt/nas`**

改 `/opt/nas/scripts/restic-backup.sh`，`BACKUP_PATHS` 加 `/opt/nas`，排除三项：

```bash
--exclude /opt/nas/cache          # 62G qbit 下载缓存
--exclude /opt/nas/immich/ml-cache # 12G ML 模型可重下
--exclude /opt/nas/.git            # 8G，GitHub 已有
```

实际备份量 ~15 G（各 db + 配置），restic 去重压缩后更小。下游 restic-mirror（rsync）/ restic-onedrive（rclone）复制整个 critical-mirror 仓库，无需改，自动跟随同步。

**2. 重写 `.gitignore`（v2，198 行）**

- 默认排除所有 backup / db / cache / 敏感
- 通用规则 `**/backups/` 等使新应用自动适用
- 白名单只放行配置文本（compose / Definitions / jellyfin 插件 xml）
- 移除旧版"放行 arr backup zip"白名单（问题根源）+ immich sql.gz 白名单（restic 已覆盖）
- 补排除 `*.bak` / `*.bak-*` 临时备份

**3. git filter-repo 清历史**

```bash
apt install git-filter-repo   # Debian 源有
git filter-repo --force --invert-paths --path <目录>
```

清除 6 个 backup 目录（navidrome / kavita / sonarr / radarr / prowlarr / bazarr 的 backups）。`.git` 从 **8.2 G → 7.2 M**。filter-repo 会移除 origin，需重新加。

**4. force push**

```bash
git remote add origin <url>
git push origin main --force
```

### 架构定型

- **git** = 配置文本版本控制（compose / xml / json / 脚本），7.2 M
- **restic** = 应用数据 + 媒体备份 → critical-mirror → secondary + OneDrive

### 备份链时刻

```
restic-backup → critical-mirror
                  ├─ restic-mirror   rsync  [06:00] → secondary
                  └─ restic-onedrive rclone [07:00] → OneDrive
git-backup [04:00] → GitHub
```

### HDD 休眠决策

- sdc（pool-main）`APM not supported` 不休眠常转，SMART 满格（坏道 0 / Load_Cycle 2044 / Start_Stop 2014 / 通电 3805h）
- **结论**：听歌读取不伤 HDD 不需迁 SSD（读取不磨损盘，寿命靠备份兜底）
- 建议 sdb / sda（备份盘，一天唤醒 1-2 次）可设休眠省电；pool-main 不建议（关联服务多，白天有零星后台访问会频繁唤醒）
- 待确认 sdb / sda 是否支持 hdparm 休眠；可选给监控加 SMART 坏道告警
