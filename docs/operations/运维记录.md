## NPM、DDNS 与 Homeland

- NPM 位于 `/opt/nas/npm`，历史端口映射为 `8443:443` 与 `192.168.50.33:81:81`。同网容器仍可访问 `npm:81`，用户此前接受此风险；不要据 LAN 绑定宣称完全隔离。
- Homeland 上游为 `http://homeland_frontend:3000`，basePath `/home`，反代保留 URI 和 `Cf-Access-Jwt-Assertion`。源码与 Compose 仍由 [Homeland](https://github.com/jds5/homeland) 维护。
- 根域 `rokano.org` 使用单独证书，`*.rokano.org` 不覆盖根域；`origin-home.rokano.org` 使用通配符证书。DNS Challenge 与续期由 NPM 管理。
- 2026-08-23 曾备份 NPM 数据库到 `/data/database.sqlite.backup-20260823-origin-home`；文件是否仍在需现场核对，不能代替新变更前备份。
- `ddns-go` 位于 `/opt/nas/ddns-go`；旧记录曾把根域与四个媒体子域一起更新到家庭 IP，但根域后来改为自选 Cloudflare IP。后续必须核对实际 DDNS 管理列表，避免旧任务把优选入口覆盖成家庭 IP。旧公网 IP 和 DNS 表已从维护文档删除。

### 2026-08-31 写入 403 修复

`origin-home` Proxy Host 7 的 `/home` 曾存在 `limit_except GET HEAD OPTIONS { deny all; }`，导致合法 Writer 在 NPM 层被拒绝，应用收不到请求。原记录通过 NPM API 只移除了 `/home` 的该限制，保留 assertion 透传，未改 Stock 的只读规则。

执行 `nginx -t`、重启 NPM 后，匿名 POST 仍由应用拒绝为 403；真实 Access Writer DELETE 返回 200，数据库目标记录消失。后续不能再对 Homeland 的整个 `/home` 无条件禁写，管理区写入由应用 JWT + CSRF 校验。源站公开读的防绕过仍须单独补齐。

### 公网故障时临时阅读

从可信 LAN 或已验证的 VPN 建立 SSH 隧道。容器 IP 会随重建改变，先在 NAS 查询 `homeland_frontend` 对应网络的实际地址，再替换下面占位符；不要复制旧文档中的固定容器 IP。

```bash
ssh -N -L 127.0.0.1:33000:<容器IP>:3000 yao@192.168.50.33
```

浏览器访问 `http://127.0.0.1:33000/home/docs`；这里只提供临时阅读，不修改 Access 配置或创建公网入口。

## 备份与恢复

原记录中的分工是 Git 管配置文本，restic 管应用数据与媒体备份；Git 不纳入数据库、自动 backup、缓存或凭据。

```text
restic-backup [02:00] → critical-mirror
                         ├─ restic-mirror [06:00] → secondary-mirror
                         └─ restic-onedrive [07:00] → OneDrive
git-backup [04:00] → GitHub nas-config
```

`restic-backup.sh` 已记录加入 `/opt/nas`，排除 `/opt/nas/cache`、`/opt/nas/immich/ml-cache`、`/opt/nas/.git`。镜像和 OneDrive 任务复制整个仓库，随扩展跟进。脚本未在本仓库，应从受控配置源核对，不根据文档重建生产脚本。

历史故障是应用自动备份进入 Git 导致膨胀、推送失败；当时已清理 Git 历史。这里不保留 `filter-repo --force` 或强推操作配方，正常维护应先修正忽略规则，数据由备份系统保护。

## 排障与监控遗留

- Tailscale DNS：历史容器保留 `100.100.100.100` 后发生域名解析失败。调整 DNS 接管后逐个核对受影响容器的 `resolv.conf` 与外部解析，按需重建，避免不加区分重建全部生产服务。
- Sonarr 报错需读 Sonarr 本身日志，不能只根据 Seerr 转述的 503 判断；历史故障涉及 `skyhook.sonarr.tv` 解析。
- Uptime Kuma 曾有 `socket.getPeerCertificate is not a function`；备份 Push 重试曾调整为 2、间隔 3600 秒，恢复情况与心跳是否正常仍需核验。
- 旧 Uptime Kuma Push Token 曾写入 Git 历史；当前文档脱敏不代表完成轮换。需要验证旧值失效及新心跳有效，不记录任何真实值。
- diun / uptime-kuma / dozzle / beszel-agent 曾挂载 Docker socket，权限收窄待核验。
- HA 留作家装后的事项，尚不按已部署服务维护。基础控制应避免依赖 NAS 单点；需要时另做实施方案。
