### 2026-08-31 写入 403 修复

`origin-home` Proxy Host 7 的 `/home` 曾存在 `limit_except GET HEAD OPTIONS { deny all; }`，导致合法 Writer 在 NPM 层被拒绝，应用收不到请求。原记录通过 NPM API 只移除了 `/home` 的该限制，保留 assertion 透传，未改 Stock 的只读规则。

执行 `nginx -t`、重启 NPM 后，匿名 POST 仍由应用拒绝为 403；真实 Access Writer DELETE 返回 200，数据库目标记录消失。后续不能再对 Homeland 的整个 `/home` 无条件禁写，管理区写入由应用 JWT + CSRF 校验。源站公开读的防绕过仍须单独补齐。

### 公网故障时临时阅读

从可信 LAN 或已验证的 VPN 建立 SSH 隧道。容器 IP 会随重建改变，先在 NAS 查询 `homeland_frontend` 对应网络的实际地址，再替换下面占位符；不要复制旧文档中的固定容器 IP。

```bash
ssh -N -L 127.0.0.1:33000:<容器IP>:3000 yao@192.168.50.33
```

浏览器访问 `http://127.0.0.1:33000/home/docs`；这里只提供临时阅读，不修改 Access 配置或创建公网入口。

### 4G 失败阶段确认（2026-09-16）

用户更新 0.2.1 后反馈 `E_TCP_TIMEOUT`：实际 TCP connect 超时，尚未进入 SSH 握手/主机指纹校验/公钥认证，因此本次失败不应通过更换密钥或放宽认证处理。此前同一 4G 网络的域名和公网 IP 直连都失败，不能仅归因于 DNS。

再次只读核对：A 记录仍为 `122.96.13.143`；NAS 侧访问公网 2257 收到本机 OpenSSH banner，8443 TCP 也可连接，本机 IPv4/IPv6 的 22 仍监听。以上仍只是 NAS 侧回环证据，不能证明手机来源的入站路径或 WAN 防火墙已放行。

用户随后确认：没有 VPN/代理，App 移动数据已允许，4G 下 NAS 网页可打开。路由器为 ASUS RT-AX86U Pro，用户设置外部 2257、内部 22；完整来源限制及 WAN 防火墙尚未直接核验。Windows 按热点对照步骤反馈 `RemoteAddress=122.96.13.143`、`RemotePort=2257`、`TcpTestSucceeded=False`，独立客户端也复现 TCP 失败；Ping 超时不能单独证明主机离线。

下一步需在 NAS 的 `enp1s0` 短时观察 22 端口的 SYN/SYN-ACK/RST，再从 Windows 重试，以区分入站请求未到达与 NAS/回程问题。之所以观察 22 而非 2257，是因为路由器已做目的端口转换。当前用户直接抓包被权限拒绝，`sudo -n` 也要求密码，故未实际抓取；需管理员在 NAS 终端执行，不向助手提供密码。尚未定位丢包位置，未修改网络配置。


### 手机 SYN 已到达 NAS（2026-09-16）

用户在 NAS 抓包期间用手机 App 重试，观察到同一外部来源向 `192.168.50.33:22` 连续重传 SYN，未在 `enp1s0` 看到相应 SYN-ACK 或 RST。此证据说明该次公网请求已经过转发送达 NAS，不能继续将问题仅归因于 App 或入站端口转发未生效。

只读现场核对：SSH 仍监听 IPv4/IPv6 的 22；到该手机公网来源的普通 IPv4 回程路由为 `192.168.50.1 / enp1s0`。UFW 服务 active，`/etc/ufw/ufw.conf` 为 `ENABLED=yes`，配置默认入站策略 `DROP`；firewalld、fail2ban、nftables 服务 inactive（不代表内核没有 nftables 规则）。Tailscale active，所查普通回程没有走 tailscale0。

### 确认 UFW 缺少公网 SSH 允许规则（2026-09-16）

用户提供 `sudo ufw status verbose`：UFW active，默认 deny incoming；SSH 22/tcp 只允许 `192.168.0.0/16`，并有该 LAN 范围的全端口允许规则，未有公网 IPv4 来源访问 22 的允许规则。这与 LAN 成功、4G SYN 到达但不回复的现象一致，已定位阻断原因。

回滚会回到备份时的账户、观看进度和库状态；先停止 Jellyfin，并保留升级后的配置目录，不能只切换旧镜像。以下命令在 NAS 以 `yao` 执行：

```bash
set -e
jf_backup=/home/yao/.nas-maintenance-backups/jellyfin-20260918-150917
cd "$jf_backup"
sha256sum -c config.tar.sha256
docker image inspect jellyfin/jellyfin:rollback-20260918 >/dev/null
docker stop --timeout 60 jellyfin
mv /opt/nas/jellyfin/config "$jf_backup/config-after-upgrade-$(date +%Y%m%d-%H%M%S)"
tar --acls --xattrs -xpf "$jf_backup/config.tar" -C /opt/nas/jellyfin
cp "$jf_backup/docker-compose.yml" /opt/nas/jellyfin/docker-compose.yml
# 原配置用 latest；回滚时改为已保留的旧镜像，不重新拉取 latest。
sed -i 's|image: jellyfin/jellyfin:latest|image: jellyfin/jellyfin:rollback-20260918|' /opt/nas/jellyfin/docker-compose.yml
docker compose -f /opt/nas/jellyfin/docker-compose.yml config -q
docker compose -f /opt/nas/jellyfin/docker-compose.yml up -d --no-deps --pull never jellyfin
curl -fsS http://127.0.0.1:8096/health
curl -fsS http://127.0.0.1:8096/System/Info/Public
```
