# NAS 网页终端开发与内部部署（2026-09-29）

## 需求与现场

用户要求参考 `~/code/home` 实现整个页面由 Cloudflare Access 保护的在线 tmux 终端，并确认使用 `terminal.rokano.org`、沿用 home 的允许邮箱。现场实际参考仓库为 `/home/yao/code/homeland`，tmux 会话名为 `home`；没有修改 Homeland 代码或服务。新应用在 [apps/web-terminal](../../apps/web-terminal/README.md)，规划及开发前写入面审计在 [PLAN.md](../../apps/web-terminal/PLAN.md)。

核验环境：NAS `ynas`，宿主用户 UID/GID 1000，tmux 3.5a，socket `/tmp/tmux-1000/default`，`exit-unattached off`。NPM 当前宿主映射 8443→443、LAN 81 管理端口，现有通配符证书覆盖 `*.rokano.org`。没有使用历史配置直接修改路由。

## 实际完成

- 实现完整网页终端、会话列表、手机快捷键、中文输入框、粘贴与显式回车、全屏和手动重连。连接已有 tmux，不解析 Codex 协议，支持终端初始化选项。
- HTML、资源、API、WebSocket 均由 jose RS256 验签；校验 issuer、独立 Audience、exp/nbf、已签名邮箱白名单。缺少配置全部 403。POST 校验精确 Origin 与 CSRF header，WS 校验 Origin 和身份绑定的一次性 30 秒票据。连接受 JWT 到期及最长 15 分钟限制。
- tmux client 不踢其他客户端，不覆盖宿主 session 环境；服务端队列内再次核对 PID/创建时间。断开仅结束该 client。测试发现 socket ctime 随 tmux 连接/断开变化，已改用 inode/birthtime 等稳定身份，避免正常重连被拒绝。
- 添加专用 Worker 与 NPM 配置模板及回滚步骤；Worker 覆盖回源 Secret，保留 Origin/JWT/WS 子协议。同步统一 Access 手册的整站私有应用要求。
- 部署镜像 `nas-web-terminal:0.1.0`、容器 `nas_web_terminal`，独立网络 `nas-terminal-front` **当前只有该容器**；未连接 NPM，无宿主端口映射。非 root 1000:1000、只读 rootfs、capabilities 全部移除、no-new-privileges、内存/PID/CPU 限额，仅挂载 tmux socket 目录。
- 本地 `.env` 权限 600，继承 home 的 Team Domain，独立 AUD 和邮箱白名单仍为空，**生产容器处于拒绝所有请求状态**。没有把 home 的 Audience 复制给新应用。

## 回滚

当前只需在 `apps/web-terminal` 执行 `docker compose down`，确认 `nas-terminal-front` 无成员后 `docker network rm nas-terminal-front`。这会断开网页 client，不会终止宿主 tmux 会话。保留本地 `.env` 供后续恢复，不删除宿主 socket；没有需要恢复的既有生产配置。未来接入公网时先备份 NPM/Worker/Access 独立配置，再按应用 README 的回退顺序操作。
