# NAS 网页终端安全审查

日期：2026-09-29；代码基线 `bd25f72`，运行镜像 0.4.0。

范围：假设 Cloudflare Access 的服务、签名密钥与验签体系未被攻破，检查自研终端、宿主授权、同域应用、源站和会话生命周期。应用配置/私钥内容未读取；没有攻击生产会话、执行提权或进行压力测试。此审查记录风险，不调整部署或既有域名决策。

> 以下主体为 0.4.0 历史审查；0.5.1 将已鉴权连接的期限改为独立 24 小时，撤销窗口变化见文末。

## 结论与优先级

未在本次审查及既有回归测试中发现匿名伪造 JWT 即可进入终端的路径。主要风险是有效浏览器会话、同源应用或受信任服务被利用后，权限可扩展到整个 NAS。Access 可信不等于浏览器、NPM、应用进程和宿主用户可信。

### 高：共享 Origin 放大同域 XSS 的影响

`/terminal`、`/home`、`/stock` 同属 `https://rokano.org`。`server/app.mjs` 的 Origin/CSRF 校验只隔离不同 Origin，不能区分页面路径。若用户有可用终端登录态，同域其他页面被注入恶意脚本，可用浏览器凭据请求终端列表、取得连接票据并操作 WebSocket；无需读取 HttpOnly Cookie 或知道 JWT 内容。独立 Audience 阻止拿其他应用 token 直接冒用，但不阻止浏览器替攻击脚本带上终端自身登录态。

这是已确认的部署边界与条件性攻击路径，**未证明 home/stock 存在 XSS**。终端本页 CSP 不约束其他页面的脚本。安全整改优先考虑独立 Origin；若坚持当前路径，必须把同域所有应用当作管理面一并审查和维护，Cookie Path 或额外可由 JS 设置的请求头不能形成同源隔离。本次不变更用户此前要求的路径部署。

### 高：终端权限实际可达 NAS root

现场 `id` 确认 yao 属于 docker 组；`/var/run/docker.sock` 为 `root:docker 660`，Docker 运行配置未启用 rootless。网页 SSH 登录 yao、tmux 连接 yao 的既有会话，获得其 Docker 能力后可达宿主 root。非 root Web 容器、只读根目录、不挂 Docker socket 都不能约束已经通过 SSH/tmux 到达宿主的命令。

这是功能权限边界，不是新发现的匿名提权漏洞。不同允许邮箱目前也没有会话 ACL，全部相当于 NAS 管理员。若需降低影响范围，需要单独低权限 Unix 用户、独立 tmux server 与项目权限，且不能继续授予生产 yao 的 socket；只修改容器 UID 或移除容器 capabilities 无效。需要部署操作时再经受限提权通道授权。

依据：[Docker 官方关于 docker 组 root 级权限的说明](https://docs.docker.com/engine/install/linux-postinstall/)。

### 高（需前置失陷）：NPM/应用进程也是管理信任链的一部分

实测 front 网络仅 NPM 与 Web 容器。NPM 可处理终端页面、JWT、WebSocket，应用可使用专用 SSH key 和 tmux socket。若 NPM 被控制，可篡改页面并借用户登录态操作；若终端服务发生进程级代码执行，可直接经 socket/SSH 到达 NAS，Access 无需失陷。当前未发现可利用的 NPM 或 Node RCE；这是失陷后的传播路径。

专用 SSH key 的 loopback 来源、restrict/pty、固定主机公钥是有效限制，但不能限制获授权 shell 的命令。socat 转接容器使用 host 网络，虽未监听 TCP 且权限已收窄，其代码执行仍有主机网络可达性。优先减少管理代理的其他负载、持续维护依赖，并结合上项降低宿主权限。

### 中高：有效 JWT 被窃取后的重放与撤销滞后

`server/auth.mjs` 本地验证签名/声明，不查询撤销状态；Origin 对非浏览器客户端不是秘密，可以自行填写。`server/terminal.mjs` 在建立连接时核定 JWT 到期和 15 分钟上限，没有持续检查 Access 注销/撤销。页面注销本身不提供服务端按身份断开所有 peers 的接口，其他标签页或独立客户端的已建立连接可能继续存在至截止时间。

如果攻击者已拿到有效终端 JWT，且能访问既有直接源站路径，可在 JWT 到期前重放；一次性 WS ticket 只阻止 ticket 重放，不阻止 JWT 重新换票。**15 分钟是单条连接上限，不是被盗 JWT 的总可利用期限**：源站只验签时，仍有效 JWT 可以再次建连直至 exp。此条件性路径由代码及既有源站部署推导，未使用真实 JWT 做重放试验，未读取实际 Access 会话时长。

建议源站增加受认证的边缘到源站约束，避免终端源站作为独立 JWT 重放入口；增加应用侧按身份撤销/断开能力并使既有票据失效。缩短期限有帮助，但不能代替撤销机制。Access 官方说明：[应用令牌与源站验签](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/)。

### 中：资源限额仍有空缺

有 WebSocket 数量/帧大小/输出背压、上传 4 并发/20 MiB 单文件/512 MiB 配额、history 限频及容器资源上限。但是 GET sessions 每次读取宿主 tmux 元数据，无请求速率上限；输入/resize 帧没有频率限额；历史捕获虽限频仍调用宿主 tmux server。容器资源限制不能约束宿主 tmux 的全部工作。未认证源站请求也需要 HTTP/JWT 处理，当前终端 NPM location 无 limit_req/limit_conn。

恶意已登录客户端可影响可用性；无需假定攻击者能绕过 Access，公开源站上的未认证洪泛也有成本。未对生产进行压测，不能量化击穿阈值。建议 API/连接/resize 限频、短期缓存会话列表、源站连接上限，并保留正常终端吞吐。

### 中低：留存、文件验证和审计不足

上传成功后长期保存，移除草稿不会删除磁盘文件；文件 600、目录 700 且无下载 URL，防止匿名读取，但同一 yao 用户的进程和历史对话仍可读，敏感截图可能长期留存。上传只检查 MIME、少量魔数及字节限额，不完整解码，不限制图片像素；不能将其称作完整图片安全验证。消息提交前仅比对文件大小，已保存 SHA-256 未再次校验，不能保证同 UID 修改后的文件内容仍与上传时相同。这里的同 UID 攻击者本来就有广泛权限，不单独视为新的远程提权。

终端/代理刻意不记录命令、JWT、输出，隐私边界合理，但缺少结构化的连接建立/断开/拒绝/撤销事件，事后难以定位异常。建议提供明确的留存/手动清理流程、图片尺寸/解码约束、低敏感度安全事件审计；不要因此记录原始命令、终端内容或登录凭据。

## 已验证的防护

- RS256、issuer/audience、exp/nbf、允许邮箱；缺少配置拒绝，所有页面/资源/API/WS 都有鉴权。
- POST 精确 Origin 与 CSRF header、WS 精确 Origin、30 秒绑定身份的一次性票据、票据消费在异步工作前完成。
- 目标使用固定二进制/参数数组；SSH 主机/用户/密钥不可由浏览器指定，StrictHostKeyChecking、BatchMode、禁用转发。
- 终端历史和名字以 textContent 渲染；0.5.0 Codex Markdown 通过 Marked + DOMPurify 标签白名单渲染，不插入未经净化的 HTML；上传路径随机、wx 创建，不能用客户端名字决定路径。
- 现场 Web 容器 UID 1000、只读根、cap_drop ALL、无公开端口；专用 SSH 目录 700/key 600/传输目录 700，图片目录 700。
- 生产容器带伪造 assertion 的页面和会话 API 请求均 403。
- 18 项隔离 Node 测试全部通过，包含鉴权、票据、到期、上传归属、历史读取等；没有向生产会话发键。
- `npm audit --omit=dev --json` 当次查询报告 0 个已知漏洞，仅覆盖 npm 生产依赖。未运行 OS 镜像/CVE 扫描，不覆盖 Debian/OpenSSH/tmux/socat/NPM、未知漏洞或业务逻辑缺陷。

## 建议顺序

1. 明确该网页等同 NAS 管理入口；不要把普通访客或协作者加入同一允许列表。
2. 处理共享 Origin 的管理信任边界；审查 home/stock 和共享 NPM，或另行决定隔离 Origin。
3. 为一般工作建立低权限终端环境，管理权限按需要单独授予。
4. 加固边缘到源站约束、增加应用撤销与全连接关闭。
5. 补齐限频、安全事件审计、图片留存/验证与镜像扫描。

未修改应用代码、服务、防火墙、Access、域名或凭据。本次只新增审查文档及导航。


## 0.5.0 对话阅读增量复核（2026-09-29）

原始 Codex 对话通过已有固定、严格验签的本地 SSH 通道读取，未挂载整个 Codex 目录，也不允许客户端指定路径、主机或 thread ID。复用安卓桥接的进程树/后台端点关联；前后核对 tmux 身份和日志绑定，分页绑定同一记录。只输出公共完成消息，排除系统、推理和工具记录；题答信封转为文字。切换/断开取消 SSH 读取，并通过 epoch/requestId 丢弃旧结果。每连接一项读取、至少 1 秒间隔，全服务并发上限 2，读取/输出/时间均有上限。跨身份仍沿用现有 Access 人类邮箱策略，不提供多 Unix 用户隔离。

Markdown 原始 HTML 转义，图片仅文字占位；Marked 输出由 DOMPurify 以固定标签/属性白名单生成 DOM。无 SVG、MathML、表单、脚本、事件属性、style 或 id；链接二次校验为无用户名/密码的 HTTP(S)，禁用本地路径及危险协议，并设 noopener/noreferrer。不自动请求外部资源。用户消息使用 textContent。代码复制需点击，clipboard-write 仅 self，clipboard-read 保持禁用。宿主读取器导入桥接模块，但入口仅执行读取，不开放其输入/按键函数。已有 yao/SSH 的权限边界未缩小，也未宣称其构成沙箱。


## 0.5.1 连接期限变更（2026-10-07）

按用户明确要求，握手成功后的连接不再受原 JWT exp / 15 分钟上限截断，固定由服务端在建连 24 小时后关闭。心跳每 15 秒发送，连续 90 秒没有 Pong 才清理；心跳和切换不能续期。HTTP 和新握手仍验证 JWT 有效期，未新增匿名路径或客户端提供期限的入口。

这是明确的安全边界变化：Access 注销、JWT 到期不再终止已建立连接，其权限最多继续存在 24 小时。旧 JWT 到期后不能新建连接，但到期前建立的连接可继续；被盗 JWT 的总影响窗口不能简单视为从盗取起 24 小时。紧急撤销执行 `docker stop nas_web_terminal`，会终止网页连接及临时 SSH，不终止已有 tmux 任务。原有同域信任、源站重放、宿主权限等风险仍存在。
